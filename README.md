# Internship Agent

Internship Agent 是一个本地运行的实习岗位推荐 MVP。v0.4 默认读取实习僧公开岗位页面，记录跨运行的新岗位与岗位变化，并生成 Markdown 日报。模拟岗位仍可用于离线测试。

## 项目结构

- `collectors/`：采集器接口、实习僧公开页面采集器与模拟数据。
- `models/`：统一的 `Job` 数据结构。
- `pipeline/`：从原文提取标签、标准化、去重、过滤、评分与跨运行状态。
- `reports/`：Markdown 日报生成。
- `config/`：用户偏好示例；本地 `profile.yaml` 不提交到 Git。
- `data/`：日报、岗位状态与详情页缓存；后两者不会提交到 Git。

## 安装和运行

需要 Python 3.11+。在项目根目录执行：

```bash
pip install -r requirements.txt
cp config/profile.example.yaml config/profile.yaml
python main.py
```

Windows PowerShell 可将 `cp` 换成 `Copy-Item`。从 v0.1 升级的用户需要按新示例迁移本地 `config/profile.yaml`；新结构区分首选与可接受地点、强偏好与中等偏好方向。运行后查看 `data/daily_report.md`。测试命令为 `pytest`。

默认最多请求 30 条详情页。小规模验证或离线模拟可用：

```bash
python main.py --max-jobs 10
python main.py --pages 2 --max-jobs 50
python main.py --source mock
```

实习僧采集器只请求“法务、律师、合规”与“东莞、广州、深圳”的搜索组合，默认各一页。`--pages 2` 最多读取两页，只有公开搜索页显示有下一页时才继续；`page=2` 已通过公开页面结果验证。搜索页只发现岗位链接；标题、公司、每周天数等字段都从详情页读取。请求间隔至少约一秒，遇到 403、429、验证页或重定向会停止，不会登录、携带手工 Cookie 或绕过限制。搜索页显示“最新”和“一月内”选项，但公开 HTML 没有给出可核实的 URL 或表单参数，所以目前仍使用默认排序。

搜索页每次都重新请求。成功解析的详情页在 `data/cache/shixiseng/` 中缓存 24 小时，过期后重新请求；运行统计中的 `cache_hits` 表示复用数量。`data/state/jobs.json` 按来源岗位 ID（缺失时按规范化链接）记录首次发现、最近发现、招聘内容摘要与最近分数。首次运行会把当前岗位标为 `new`，后续相同内容为 `seen`，关键字段或正文变化为 `updated`。状态文件损坏时程序会明确报错，以免误覆盖已有记录。

## 当前规则

- 同一公司、标题、城市的岗位只保留首次出现的一条。
- 实习僧岗位优先按来源岗位 ID 去重，其次按规范化链接，最后按公司、标题、城市。
- 截止日期已过、明确要求其他专业、明确异地且不能远程的岗位被过滤。截止日期优先从“投递要求”读取，缺失时搜索岗位主体的可见文字。未注明的地点、远程方式或每周天数不会被猜测。
- 页面明确显示已下线的岗位被过滤；无法判断状态时保留未知。
- 页面刷新时间单独记录，不当作发布时间。刷新时间距运行日期超过 180 天时，日报显示需确认岗位有效性的提醒，但不会单凭此项过滤岗位。
- 时效状态按页面刷新时间分为 `fresh`（30 天内）、`recent`（31–90 天）、`stale`（91–180 天）、`very_stale`（超过 180 天）或 `unknown`；在四项基础分之上分别调整 0、0、-3、-8、-2 分。
- 每周天数超过上限的岗位保留，但时间地点项计 0 分，并显示问题。
- 若每周天数超限且方向分至少 17、内容分至少 10，岗位会进入日报的“时间不合适但值得关注”，最多显示 5 条。
- 基础分由资格匹配 0–30、方向匹配 0–25、时间地点 0–25、岗位内容 0–20 相加，再应用时效调整得到最终分；65 分及以上计入日报的“推荐”。未知字段得到中性分，不会被写成已确认的优势。
- 内容分把法律研究、检索和法规研究等同类任务合并计分，不因同义词重复刷分；普通材料整理不会被当成负面任务。日报分列今日新发现、岗位变化、Top 5、时间冲突机会和已跟踪总数。
- 业务与任务标签只从 `raw_text` 中的明确词语提取，`evidence` 保留相应原文片段。无原文依据的传入标签会被移除。
- 单条岗位的异常链接或日期会记录到 `data_quality`，相应字段视为未知；整批处理继续。缺少岗位 ID、标题、公司或可核对的招聘原文时，跳过该条并打印 warning。

每次运行会输出字段完整率以及 `expired`、`inactive`、`major_mismatch` 等硬拒绝计数。完整率只表示字段已取得，不保证该字段事实正确；应结合原文核查。实习僧页面结构、字体或正文写法变化可能让部分字段保持未知或导致单条解析失败；采集器会打印 warning 并继续。关键词提取不能完整理解否定、同义词和复杂学历条件；对这些内容仍需人工核实。`background` 已保存在用户偏好中，当前没有岗位背景要求字段，因此暂不参与评分。项目没有接入 AI API。
